# 04 · 让滚动成为动画的时间轴

[返回首页](../README.md) · [上一步：做模型](03-build-the-model.md) · [下一步：看案例](05-examples.md)

网站阶段要把设计图和真实模型接起来。最重要的一条规则是：**同一个滚动进度，永远对应同一个画面状态。** 这样慢慢滚、快速滚、向上滚，模型都不会越跑越远。

## 先认识几个工具

| 名称 | 在这里做什么 |
| --- | --- |
| React + Vite | 组织页面并运行本地开发预览 |
| Three.js | 在浏览器中渲染 3D 场景、相机和材质 |
| React Three Fiber | 在 React 中组织 Three.js 场景，`useFrame` 参与逐帧更新 |
| Drei | 提供 `ScrollControls` 和 `useScroll` 等现成工具 |
| GLB | 装入网页的模型与节点层级 |

一个容易混淆的地方：[`useFrame` 属于 React Three Fiber](https://r3f.docs.pmnd.rs/api/hooks)，而 [`ScrollControls` 与 `useScroll` 属于 Drei](https://drei.docs.pmnd.rs/controls/scroll-controls)。原文把它们放在一起介绍，这里分开写清楚。

## 跟着做

1. **把资产放到同一个项目。** 确认六张设计图、设计规范、准确文案、`.blend`、`.glb` 和 `asset-index.json` 都能被当前项目读取。
2. **生成基础页面。** 先搭好六个连续章节和导航，用真实 HTML 文字排版。设计图用于参照，不能直接整张贴作网页。
3. **加载真实 GLB。** 检查模型、贴图、比例、朝向和部件名是否正常。先只展示完整模型。
4. **接入滚动进度。** 把滚动距离映射到 `0～1`，为每一屏设置进入和离开的区间。背景、文字、相机和模型可以采用不同的位移幅度。
5. **增加拆解和归位。** 对每个可动部件，始终从记录好的初始变换计算目标状态，不在“当前位置”上反复加位移。
6. **打开本地预览并调整。** 原飞书流程使用 Vite；实际命令通常是 `npm run dev`，以生成项目的 `package.json` 为准。[Vite 官方入门](https://vite.dev/guide/)说明了开发与构建流程。

可以把[提示词③：视差滚动网站](../prompts/03-website.md)发给能读取这个项目的 AI 工作环境。它应先识别现有资产，再开始写页面。

## 为什么“归位”这么重要

把滚动进度记为 `t`，展开程度记为 `e(t)`。某个部件的位置始终按这个式子求：

```text
当前位置 = 初始位置 + 展开方向 × 展开距离 × e(t)
```

`e(t)` 从 0 平滑到 1，再回到 0。只要每次都从**同一份初始位置**计算，反向滚动就能回到原处。下面是说明思路的伪代码，不是完整网页组件：

```ts
const amount = smoothstep(start, end, scrollProgress);
part.position.copy(initialPosition).addScaledVector(direction, distance * amount);
```

旋转、缩放和相机位置也遵循同样原则：根据当前进度计算目标值，避免把每一帧的增量无限累计。

## 手机和易用性

- 手机上把模型与文字重新排成上下布局，减小模型占比和视差位移；不要只缩小桌面版。
- 给模型加载过程提供进度提示，失败时给出可重试的状态。
- 把拖拽旋转等自由操作放在清楚的交互区域或模式中，避免和页面滚动抢手势。
- 对偏好减少动态效果的用户，降低或关闭强烈运动。
- 导航要能跳到章节；用键盘和触摸也应能完成基本浏览。

## 过关检查

- [ ] 六屏顺序、导航高亮和文字与设计稿一致。
- [ ] GLB 与贴图正常加载，模型没有倒置或错位。
- [ ] 快速滚动、反向滚动时，模型状态仍然连续且能准确归位。
- [ ] 爆炸图只拆真实存在的独立节点。
- [ ] 手机端文字不遮挡主体，页面能够滚到末尾。
- [ ] 已记录仍待修复的问题和实际预览地址。
