# 06 · 排错、优化与发布

[返回首页](../README.md) · [上一步：看案例](05-examples.md)

做 3D 网页时，最常见的问题并不神秘：通常是素材不一致、节点丢失、滚动状态计算方式不对，或者模型太重。先看现象，再检查对应环节。

## 常见问题速查

| 你看到的问题 | 先检查什么 | 可以怎么修 |
| --- | --- | --- |
| 六张设计图像来自六个网站 | 是否给每张图带入第 01 屏和统一规范 | 只重做偏差的图片，并锁定色板、字体、导航、主体 |
| 曲面部件变形 | 使用的参考图是否足够，建模办法是否适合 | 补多角度参考图；复杂曲面可尝试生成工具后再修整 |
| GLB 在网页里倒置 | 导出轴向、模型原点和导入时的旋转 | 检查 Blender 的 glTF 导出设置，再在网页端确认；避免盲目重复旋转 |
| 爆炸图回滚后无法归位 | 是否在当前位置不断累加位移 | 改为“初始位置 + 方向 × 展开量(进度)” |
| 首屏加载很久 | GLB 大小、贴图尺寸、重复几何体 | 压缩贴图、减少无用细分，按需尝试几何压缩和分级加载 |
| 旋转模型时页面也滚动 | 拖拽区域与页面滚动冲突 | 设置明确的模型交互入口或限定拖拽区域 |
| AI 找不到文件 | 文件是否都在当前项目、资产清单是否过期 | 检查路径，更新 `asset-index.json`，再让 AI 读取 |
| 手机文字压住模型 | 是否只缩小了桌面布局 | 改成上下布局，缩小模型占比和运动幅度 |
| 网页文字与设计图不一致 | 生图工具的小字是否有误 | 以 `design/copy.md` 的准确文案为准 |

反馈给 AI 时，尽量说清楚**哪一屏、哪个部件、怎么复现、希望回到什么状态**。例如：“第 03 屏向上回滚时，表针停在展开位置；请用初始变换重新计算位置。”

## 把性能调到可用

先在实际目标设备上观察加载时间和滚动是否顺畅，再决定要优化哪一项：

- **模型：** 删除看不见的细节、控制多边形数；重复部件可研究实例化渲染。
- **贴图：** 减小不必要的超高分辨率贴图；需要时研究 KTX2 等格式。
- **加载：** 首屏先给出可见内容和加载反馈，大模型可考虑分级或延后加载。
- **画面：** 手机端控制渲染像素比和强运动，尊重“减少动态效果”设置。

原文列出 Draco、KTX2、InstancedMesh 等进阶方案。它们都需要在项目中实际测量和验证，不必一开始全部加入。

## 准备发布

1. 在项目目录运行 `npm run build`，确认生成可部署文件；命令以项目的 `package.json` 为准。
2. 在本地检查六屏、导航、模型加载、反向滚动、手机布局和加载失败状态。
3. 选择适合自己的静态托管平台，例如 [Vercel](https://vercel.com/)、[Netlify](https://www.netlify.com/) 或 GitHub Pages；按平台当前方案核对费用和限制。
4. 大模型如需独立托管，可放到合适的对象存储或 CDN，并核对跨域设置和缓存策略。
5. 上线后再从公开网址完整走一遍。建议使用 HTTPS；若加入 WebXR 等能力，还要核对相应浏览器的安全上下文要求。

本仓库只提供教程，并未替你的实际网站完成部署。

## 最后检查一次

- [ ] 六张设计图、规范和准确文案已保留。
- [ ] `.blend` 原工程、GLB 和资产清单可找到。
- [ ] GLB 节点、材质、方向与拆解动作正确。
- [ ] 快速滚、反向滚、触摸滚动都能到达预期状态。
- [ ] 手机端可读，模型加载失败时有提示。
- [ ] 发布页面中的产品参数与建筑数据已核对。
