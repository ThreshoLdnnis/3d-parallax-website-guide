# 02 · 设计六屏故事

[返回首页](../README.md) · [上一步：准备](01-getting-started.md) · [下一步：做模型](03-build-the-model.md)

先做设计稿，是为了让网页有一条清晰的叙事线。每屏只回答一个问题，画面就不会变成“同一张图换六个标题”。

## 六屏怎么分工

| 屏 | 访客想知道什么 | 建议画面 |
| --- | --- | --- |
| 01 · 初见 | 这是什么？ | 主体全貌、网站名称、短标题、探索入口 |
| 02 · 整体 | 它有什么特点？ | 换个角度展示主体，配一条核心介绍 |
| 03 · 结构 | 它由什么组成？ | 有资料依据的分层或爆炸图、部件名称 |
| 04 · 细节 | 最值得细看的地方在哪？ | 局部特写、材质或工艺说明 |
| 05 · 价值 | 为什么值得关注？ | 使用场景、设计亮点或文化背景 |
| 06 · 收尾 | 接下来做什么？ | 回到主体全貌、总结句、行动按钮 |

如果没有内部结构资料，第 03 屏改做**外观构成**，也能讲出好故事。

## 跟着做

1. **整理输入。** 把主题照片、结构资料和品牌内容放入 `references/`。
2. **先定整套规则。** 写下背景色、主文字色、强调色、字体层级、页面边距、导航顺序、主体材质与光线方向。六屏都沿用它们。
3. **生成第 01 屏。** 它是整套视觉的基准。满意后，再带着它和设计规范生成其余五屏。
4. **逐屏检查。** 主体应始终是同一个；不同视角可以，外形、颜色和零件数量不能无故变化。
5. **只修有问题的屏。** 不必为了修第 04 屏重做整套图。

可以直接复制[提示词①：六屏设计稿](../prompts/01-design.md)。把方括号里的主题、用途、语言和风格换成自己的内容。

## 交付物长什么样

```text
design/
├── 01-intro.png
├── 02-overview.png
├── 03-structure.png
├── 04-detail.png
├── 05-value.png
├── 06-ending.png
├── design-rules.md   # 色板、字体、导航、按钮、主体与光线规则
└── copy.md           # 每屏准确的标题、正文和按钮文字
```

生图工具生成的小字可能不准确，所以 `copy.md` 很重要：后续写网页时，以这份文案为准，而不是照抄图片中模糊的小字。

## 过关检查

- [ ] 六张独立图片齐全，尺寸和风格统一。
- [ ] 主体外形、颜色、材质和部件数量前后一致。
- [ ] 导航位置、字体层级、按钮样式一致；当前章节高亮正确。
- [ ] 六屏的信息顺序清楚，每屏有新的观察角度或内容重点。
- [ ] 第 03 屏的拆解关系有参考依据。
- [ ] 有设计规范和准确逐屏文案。

完成后，带着设计图和参考资料进入[模型阶段](03-build-the-model.md)。
